## 1. Что не так сейчас

## 3. Экранная клавиатура (PIN)

- Сетка 3×4: `1 2 3 / 4 5 6 / 7 8 9 / ⌫ 0 ✓`.
- Кнопка — минимум 64×64 px, отступ между кнопками 8 px, вся зона доступна большим пальцем.
- Поля ввода **нет вообще**: цифры набираются в состояние, на экране только точки
  `● ● ● ○`. Системная клавиатура не может выехать, потому что нет `input`.
- Автоотправка после 4-й цифры (и PIN 4 цифры, не 6 — так быстрее одной рукой).
- Ошибка: три точки становятся красными и встряхиваются, поле очищается, показывается
  «Неверный PIN». Блокировка на 30 секунд после 5 попыток подряд — от подбора.
- Тап по точкам — «стереть последнюю».
- Работает и мышью, и пальцем, и с физической клавиатуры (цифры + Backspace + Enter).

## 4. «Спросить у ИИ» — как это работает

Под каждым дайджестом — строка вопроса и лента ответов (как чат). Примеры вопросов:
«что там было про увод вправо», «покажи сообщение целиком», «сколько стоило ТО у дилера».

**Где взять исходные данные.** Дайджест знает свой канал и период. Вариантов два:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Перечитывать сообщения из Telegram по запросу** | Не храним сырые сообщения (как требует ТЗ §12). Данные всегда свежие. Ничего не растёт | Каждый вопрос = запуск workflow (~40 с) + чтение Telegram |
| **B. Хранить очищенные сообщения внутри дайджеста** | Быстрее: Telegram не нужен | Противоречит §12. Файл дайджеста вырастает в разы (сотни КБ) |

Предлагаю **A**. Ответ готовится так:

1. Вы задаёте вопрос → приложение кладёт его в приватную ветку и запускает workflow.
2. Workflow перечитывает сообщения канала за период этого дайджеста.
3. Отбирает релевантные: сначала по ключевым словам вопроса, затем модель выбирает из них
   нужные (дешёвый первый проход, точный второй).
4. Отвечает, опираясь **только** на эти сообщения, и по запросу возвращает текст сообщения
   целиком плюс ссылку `t.me/c/…` на него.
5. Ответ дописывается в ленту под дайджестом; при желании — отправляется в бота.

Защита та же, что у дайджеста: сообщения — данные, не инструкции; ответ валидируется.

Стоимость одного вопроса ≈ $0.001–0.003. Латентность ~40–60 с, поэтому в ленте сразу
появляется вопрос и индикатор «ищу ответ».

## 5. Дизайн-система (чтобы «выглядело по-другому»)

Сейчас вёрстка — карточки с полями. Предлагаю мобильный язык, а не «админку»:

- **Токены**: шкала отступов 4/8/12/16/24/32, радиусы 8/12/16/24, три уровня текста
  (крупный заголовок, основной, подпись), два уровня поверхностей.
- **Компоненты**: экран с шапкой и скроллом, нижняя навигация, шторка снизу, строка списка,
  чип-переключатель, кнопка (primary/secondary/тихая), поле, скелетон загрузки, пустой экран
  с одним действием, тост.
- **Состояния**: у каждой загрузки — скелетон; у пустого списка — одно понятное действие;
  у долгой операции (workflow) — шторка с шагами: «читаю Telegram → сжимаю → сохраняю →
  отправляю»; ошибка — там же, с кнопкой «Повторить».
- **Ритм**: нижняя навигация с иконками и активным состоянием, крупные заголовки экранов,
  разделители вместо рамок, ничего лишнего в корне.
- **Тема**: остаётся клиентская (Telegram) + системная + ручной выбор. Плюс нативная кнопка
  «Назад» Telegram вместо своих стрелок.
- **Приближение к нативу Mini App**: `BackButton`, `HapticFeedback` на нажатия клавиатуры PIN,
  `expand()` (уже есть), запрет случайного свайпа-закрытия на середине.

## 8. Порядок работ

1. Дизайн-токены и компоненты (без них каждый экран будет переделываться дважды).
2. Экран PIN с клавиатурой.
3. Навигация и разделение на «Дайджесты · Каналы · Настройки».
4. Экран «Каналы» с мультивыбором.
5. Шторка «Новый дайджест»: каналы → стиль → период.
6. «Спросить у ИИ» (бэкенд + лента под дайджестом).
7. Настройки: статус, креды, бюджет, лимиты; свёрнутые шаблоны и статистика.

## 9. Что получилось

### Ответы на пять вопросов из §7

1. **Стек.** Остались на чистом JS без сборки. Дизайн-система написана вручную
   (`assets/design.css`), примитивы — в `assets/ui.js`.
2. **Вопросы к ИИ.** Вариант **A**: сообщения перечитываются из Telegram по запросу.
   Сырые сообщения не хранятся — в ответе остаются текст ответа и **ссылки** на
   сообщения, а не их копии (TASK.md §12). Если вопрос требует дословной цитаты, она
   приходит внутри ответа.
3. **Навигация.** Три вкладки. Шаблоны и статистика не исчезли — они раскрываются внутри
   «Настроек».
4. **Каналы.** Показываются каналы, группы и форумы. Личные переписки и служебный чат
   Telegram отфильтрованы (`selectableDialogs`).
5. **PIN.** Четыре цифры, автоотправка после четвёртой, блокировка на 30 секунд после
   пяти ошибок. «Забыли PIN?» ведёт к повторному вводу токена.

### Карта экранов — как в §2, с двумя уточнениями

- Первый запуск состоит из двух шагов, а не из одного: **токен + PIN**, затем короткий
  список «что осталось настроить» со ссылками в нужные места. Список можно закрыть
  («Перейти в приложение») — он не держит пользователя заложником.
- Прогресс сборки показывает **настоящие** стадии. Для этого бэкенд пишет шаги
  `read` → `summarize` → `store` → `deliver` в файл прогона по ходу дела.

### Что изменилось по ходу работы

| Изменение | Почему |
|---|---|
| Стоимость и тариф переехали в начало списка дайджестов | Постоянная полоса внизу экрана на телефоне отнимала место, а под сгибом её всё равно не было видно. Подробная разбивка — в настройках. |
| Время везде показывается в UTC | Список показывал местное время, а внутри дайджеста — UTC: один и тот же период читался как «11:40» и «08:40 UTC». |
| Тема выбирается только в браузере | Поле `ui.theme` в `data/settings.json` осталось от прежней версии и не используется: два источника правды для одной настройки. |
| Вопросы считаются отдельно от дайджестов | Первый же вопрос сделал счётчик «дайджестов: 8» над семью дайджестами. Из бюджета они по-прежнему тратятся наравне. |
| Запись в ветку данных повторяется на 5xx | GitHub ответил 500 на запись `data/ask/request.json`, пока workflow коммитил ту же ветку. Тот же запрос прошёл со второй попытки. |
| `runWorkflow` умеет не ждать файл прогона | `telegram-list.yml` его не пишет, а ожидание съедало весь таймаут: статус «Запускаю чтение…» висел десять минут при готовом списке чатов через двадцать секунд. |
| Под ответом нет списка сообщений | Ссылки на источники превращали разговор в указатель. Ответ приходит одним сообщением; `data/ask/<id>.json` по-прежнему хранит, на какие сообщения он опирался, — это запись, а не часть интерфейса. |
| Новый ответ сам подтягивается в вид | Вопрос задаётся внизу длинной статьи; ждать, пока читатель сам доскроллит, — лишний шаг. |
| Кнопки объёмные | Плоские прямоугольники с тенью читались как «не кнопки». Теперь у каждой есть боковая стенка (`--lift`, 3px) и подсветка верхней грани, а нажатие опускает её ровно на высоту стенки — кнопка встаёт на поверхность, а не дрожит. |
| Один прогон пишет все стили, переключение — кнопками | Владелец попросил собирать сразу три дайджеста и переключаться между ними. Выбор стиля из шторки убран: спрашивать, в каком стиле писать, до того как что-то прочитано, — это выбор вслепую. Прогон читает канал один раз и спрашивает модель по разу на каждый стиль, ответы ложатся в один файл вариантами. Стиль канала (или стиль по умолчанию) идёт первым, поэтому открывается именно он. Цена честно растёт втрое: ~$0.003 за канал вместо ~$0.001 (кэш промпта не помогает — системный промпт у каждого стиля свой, и общий префикс не складывается). |
| Список дайджестов стал списком | Стоимость, строка off-peak и счётчик токенов убраны из вкладки, а затем и строка расхода из самого дайджеста. Деньги живут в настройках, куда за ними приходят специально. |
| Бюджет и лимиты убраны из настроек | Владелец просил их не показывать. Разделы удалены вместе с помощником слияния и стилями полосы. Предохранитель остался: он проверяется в раннере по значениям из `data/settings.json` и защищает от разгонного прогона. |
| Свайп удаляет сразу, внизу «Вернуть» | Владелец просил убрать и кнопку под строкой, и подтверждение. Строка едет за пальцем и краснеет, когда движение зачтено; отпустили — удалено. Путь назад вместо вопроса впереди: десять секунд «Вернуть» возвращают файл, строку в индексе и ленту вопросов. |
| Полоса прогресса вместо строк стадий | Список стадий и упоминание GitHub Actions убраны. Процент не выдуман: у каждой стадии есть вес, полоса берёт самую дальнюю подтверждённую как нижнюю границу и подползает вперёд между стадиями. |

### Проверено на живом репозитории

- вход по PIN, ошибка и встряхивание, «Забыли PIN?»;
- список чатов: загрузка из Telegram, включение и выключение канала (запись в
  `data/channels.json` проверена в ветке), шторка стиля и периода;
- сборка дайджеста со стилем **аналитический** и периодом 72 часа: `--preset-id 3`
  дошёл до раннера, дайджест собрался из 97 сообщений;
- «Спросить у ИИ»: вопрос про левую камеру, ответ по исходным сообщениям и шесть ссылок
  `t.me/c/…`;
- вёрстка на 375px, контраст (WCAG AA тестом), `prefers-reduced-motion`, скелетоны,
  тосты, клавиатура с физической клавиатуры и мышью.
